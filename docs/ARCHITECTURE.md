# Architecture

## Layers

```
research/              Python reference engine (offline, authoritative math)
  ingest/fetch_adult.py    dataset fetch + provenance manifest
  models/train.py          trains both models, exports fixtures + manifest
  models/reference_math.py manifest-driven pure-Python reimplementation (the thing
                            src/engine/ ports to TypeScript, not sklearn internals)
  models/counterfactual.py single-feature constrained counterfactual search

public/data/precomputed/  browser-shipped fixtures (model_manifest.json, a ~300-case
                            sample, threshold sweep, calibration bins) -- generated by
                            train.py, never hand-edited

src/engine/             TypeScript port of the Python reference math
  model.ts                 transformRow/logisticProba/logisticAttribution, 1:1 with
                            reference_math.py, parity-tested <1e-4 against sklearn
  counterfactual.ts         1:1 port of counterfactual.py
  useFixtures.ts            fetches the 4 fixtures via import.meta.env.BASE_URL

src/scenes/              the application UI
  Tribunal.tsx              single orchestrator: owns all cross-control state (selected
                            case, active model, threshold, perturbation, comparison,
                            calibration bin), renders the intro + nav + 6 chapters
  IntroSequence.tsx          0-12s cinematic opening, GSAP timeline
  ChapterNav.tsx              fixed rail, scroll-listener-based active-chapter tracking

src/motion/              shared motion hooks (useChapterReveal, useReducedMotion)
src/webgl/               persistent WebGL background (see below)
```

## State ownership

`Tribunal.tsx` is the single source of truth for all cross-control state. Every chapter reads
from and writes to this one component's state via props/callbacks -- there is no global store,
no context, no duplicated state. The WebGL stage reads the SAME `liveResult.proba` /
`liveResult.attribution` the 2D verdict badge and attribution bars read; it never maintains a
second copy derived independently. This is deliberate: a visual that disagrees with the number
next to it would be a worse bug than no visual at all.

Perturbation (`SYN-INT-004`) is only ever evaluated against the logistic model -- there is no
TypeScript port of the gradient-boosted model's tree internals (not public sklearn API the way
logistic regression's coefficients are). Switching to the boosting model clears any active
perturbation rather than showing a stale or fabricated result (`INTERACTIONS.yaml`'s own
cross-control rule).

## The WebGL layer (`src/webgl/`)

A deliberate, user-directed addition (see `specifications/SPEC_LOCK.md` section 7 for the full
decision history, including a self-correction). Architecture:

- `WebGLStage.tsx`: the persistent `<Canvas>`, lazy-loaded as its own bundle chunk (so
  Three.js/R3F/Drei never block first paint and never load at all on unsupported browsers or
  below a 768px viewport -- see `docs/PERFORMANCE_BUDGETS.md`). `frameloop="demand"`: no
  continuous render loop; `invalidate()` fires only on real scroll/data changes.
- `Scene.tsx`: an evidence core (icosahedron, color/scale driven by live probability) and
  attribution planes (position/color driven by live attribution values), camera position tied to
  scroll progress (`useScrollProgress.ts`).
- Fallback layering, each covering a different failure mode:
  1. `supportsWebGL()` feature-detection before any Three.js import (no WebGL -> plain CSS
     background, nothing fetched).
  2. `useIsMobileViewport()` -- below 768px, the WebGL chunk is never fetched (Atlas's own
     explicit mobile 2D requirement, also a real measured performance fix: mobile Lighthouse
     Performance was 60 with the chunk loading there, 96-97 without).
  3. `WebGLErrorBoundary.tsx` -- catches genuine React-render-phase failures in the WebGL
     subtree.
  4. A `window` 'error' listener scoped to errors originating from the WebGLStage chunk
     (checked via filename/stack) -- the actual fix for a real bug an independent review found:
     Three.js's own internal renderer can throw from inside its own requestAnimationFrame loop,
     which is NOT a React render-phase error and error boundaries cannot catch it. An earlier,
     unscoped version of this listener caught ANY page error and permanently killed the renderer;
     fixed to only react to errors actually from the WebGL chunk.
  5. Real `webglcontextlost`/`webglcontextrestored` handling with a bounded recovery window.

## Why no state management library

`Tribunal.tsx`'s state is entirely local (`useState`), passed down as props to inline-rendered
chapter sections within the same file. There is exactly one component that needs this state --
splitting it into separate chapter components with a context/store would be the premature
abstraction the project's own engineering discipline (ponytail/YAGNI) explicitly avoids. If a
future chapter needs to be extracted into its own file, lifting state at that point is a small,
local change, not a rearchitecture.
